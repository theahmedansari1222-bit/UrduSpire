# UrduSpire frontend QA report

## Verified in the generated static frontend

The following were checked using a browser automation run against the exact HTML, CSS and compiled application scripts included in `dist/`:

- All ten sidebar destinations open their own view: Dashboard, News, Published, My Research, My Notes, Writing Studio, Saved, News Sources, Author Profile, and Settings & Backup.
- The Dashboard does not remain visible behind another destination.
- The full-screen article/publication reader opens and can display the published content.
- Writing Studio inserts an uploaded PNG image into the document; the image remains visible in the published reader.
- Publishing adds a document to the Published list.
- Light/dark theme toggle works.
- Mobile navigation works at a 390 CSS-pixel viewport.
- No horizontal overflow was detected at that viewport.
- The tested run reported no browser console errors or uncaught runtime errors.
- TypeScript source check (`tsc --noEmit`) passes with the included compiler options.

## Build-environment limitation

The package is configured for Vite 8 and TypeScript 7, but the build container could not reach the npm registry (DNS `EAI_AGAIN`) to install project dependencies. Therefore a native `vite build` was **not** run in this environment. The included `dist/` was generated by transpiling the TypeScript application modules with the available TypeScript compiler and copying the unchanged stylesheet and static assets. It was then exercised by the browser checks above.

After downloading, run `npm install` and `npm run build` in an environment with npm registry access to generate the standard Vite-optimized release bundle.

## Not covered by this frontend-only QA

- Authentication, authorization, database persistence, backups on a server, and multi-user concurrency.
- Live RSS ingestion, feed scheduling, cross-device sync, publication moderation, public server-side URLs, and upload storage.
- Load, penetration, accessibility certification, and production hosting/CDN tests.

This is a frontend delivery with a pre-generated static build, not a claim that a hosted multi-user production service exists.
